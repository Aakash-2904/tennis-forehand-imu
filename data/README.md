# Data dictionary

All files here are **simulated**, not recorded. They come from the physics simulator in `src/simulate.py`,
regenerated by `export_dataset.py` with **seed 7**, the same seed and random-number chain as
`src/experiment.make_dataset(7)` and `run_all.py`. The frame features match the ones the models in
`results/summary.json` were trained on.

Because the right answers are known exactly and the player variation and sensor noise are only plausible, not fitted to real recordings,
any score computed on this data is an **upper bound** for real players.

**Setup:** 12 players × 2 sessions × 30 right-handed forehands. A butt-cap IMU at 200 Hz (±16 g, ±2000 deg/s) with an on-board
6-axis orientation filter (no magnetometer). The stream includes impact shock, noise, bias, heading drift, timestamp jitter and
about 4% bursty Bluetooth packet loss.

Regenerate: `py -3.11 export_dataset.py` (about 5 min, low memory, one session at a time).

| file | rows | size | one row is |
|---|---|---|---|
| `raw_imu.csv.gz` | 540,685 | 26.1 MB | one sensor reading that actually arrived |
| `labels.csv.gz` | 564,924 | 41.3 MB | one tick of the clean 200 Hz clock (ground truth) |
| `frame_features.csv.gz` | 282,467 | 73.6 MB | one 10 ms model frame (every 2nd tick) |
| `players.csv` | 12 | 1 KB | one simulated player |

Common keys: `player` (0-11) and `session` (0-1). Rows are ordered by player, session, then time.
Join `labels` and `frame_features` on (`player`, `session`, `sample`).

## raw_imu.csv.gz: the corrupted stream as the model receives it

| column | unit | meaning |
|---|---|---|
| `t` | s | the device timestamp, with clock skew and about 0.3 ms jitter. It is irregular, and lost readings are simply absent |
| `acc_x`, `acc_y`, `acc_z` | g | accelerometer (specific force) in the sensor frame: x along the handle toward the tip, z through the string face. Clipped at ±16 g |
| `gyr_x`, `gyr_y`, `gyr_z` | deg/s | gyroscope in the sensor frame, clipped at ±2000 |
| `quat_x`, `quat_y`, `quat_z`, `quat_w` | - | orientation reported by the on-board filter, a scalar-last quaternion (sensor → world: x toward the net, y to the left, z up). Its heading has an unknown offset and drifts, and its tilt has an error under load |
| `lost_before` | count | how many 200 Hz readings were lost just before this one (round(Δt·200) − 1). 0 means no gap |

To get back to the model's input, put the rows on the 200 Hz grid with `features.session_features(stream, n_grid)`, where
`n_grid` is the number of `labels` rows for that session, acc is in m/s² (× 9.81) and gyr is in rad/s.

## labels.csv.gz: ground truth on the clean 200 Hz clock

| column | unit | meaning |
|---|---|---|
| `sample` | index | tick number in the session (t = sample / 200) |
| `t` | s | true time |
| `phase` | 0-4 | 0 idle/ready, 1 backswing, 2 forward swing, 3 follow-through, 4 recovery. Defined kinematically: reversal = minimum of racket heading, contact = impact, end of follow-through = maximum of heading |
| `stroke_id` | 0-29 | which forehand this tick belongs to, −1 between strokes |
| `trunk_angle_deg` | deg | chest (trunk) yaw. Negative = turned away from the net (the coil) |
| `shoulder_angle_deg` | deg | horizontal shoulder rotation |
| `wrist_angle_deg` | deg | wrist lag / release |
| `racket_heading_deg` | deg | racket heading alpha = trunk + shoulder + wrist (exact) |
| `head_speed_ms` | m/s | speed of the centre of the strings |
| `clean_acc_x/y/z` | g | perfect accelerometer (no noise, no impact, no clipping), sensor frame |
| `clean_gyr_x/y/z` | deg/s | perfect gyroscope, sensor frame |
| `clean_quat_x/y/z/w` | - | true sensor orientation (scalar-last, includes the small mounting offset) |

The `clean_*` columns are used only for the "perfect sensor" control in the trunk-rotation experiment.
Stroke boundaries (onset, reversal, contact, end of follow-through, end) are the first tick of phases 1, 2, 3 and 4 inside a stroke, plus the tick after its last one.

## frame_features.csv.gz: the 60 model features

| column | meaning |
|---|---|
| `frame` | frame number in the session (10 ms steps) |
| `sample` | the 200 Hz tick at the frame centre (= 2 × frame) |
| `t` | s, = sample / 200 |
| `phase` | true phase at the frame centre (the training label) |
| `missing` | 1 if the frame sits inside a gap longer than 50 ms. The HMM treats these frames as "no evidence" |
| 60 feature columns | names exactly as returned by `features.frame_features` (see below) |

All features are heading-free, because absolute heading is not observable.
* **Instant (13):** `gyr_mag` (deg/s), `yaw_rate` (deg/s about gravity), `acc_mag` (g), `lin_mag` (gravity-free g), `lin_vert` (vertical gravity-free g), `elev` (tip elevation, deg), `face_tilt` (deg), `gyr_x/y/z`, `acc_x/y/z`.
* **Windows (36):** `{gyr_mag,yaw_rate,acc_mag,elev,face_tilt,jerk}_{m,s}{5,21,61}`: centred mean (`m`) and std (`s`) over 5/21/61 samples (25/105/305 ms). `jerk` is |Δacc| between samples in g, the impact detector.
* **Past vs future (8):** `{yaw_rate,elev,gyr_mag,face_tilt}_{past,fut}`: 150 ms mean before and after the frame.
* **Heading change (2):** `dyaw_past`, `dyaw_fut`: deg turned about vertical in the last and next 300 ms.
* **Saturation (1):** `sat_frac`: fraction of samples within ±52 ms at the 16 g / 2000 deg/s limit.

Short gaps (≤ 50 ms) are linearly interpolated before features are computed. Values are float32, written with 7 significant digits.

## players.csv: player parameters (drawn uniformly at random, seed 7)

| column | unit | meaning |
|---|---|---|
| `player` | - | id |
| `coil` | deg | trunk turn-away at the end of backswing |
| `trunk_contact` | deg | trunk yaw at contact |
| `trunk_ft` | deg | trunk yaw at end of follow-through |
| `sh_bs` | deg | shoulder rotation at end of backswing |
| `sh_ft` | deg | shoulder rotation across the body at the finish |
| `wrist_lag` | deg | peak wrist lag in the forward swing |
| `arm_len` | m | shoulder-to-hand length |
| `tempo` | × | multiplier on backswing, follow-through and recovery durations |
| `fwd_dur` | s | forward-swing duration |
| `grip_roll` | deg | constant face roll from the grip |
| `ft_high` | deg | arm elevation at the finish |
| `lead` | s | how far the trunk leads the racket (kinetic chain) |

Each stroke also varies randomly: an intensity of 0.75-1.1 and about 7% jitter on every joint target.
Idle periods include distractors (racket twirls, ball bouncing, small shadow swings), labelled idle.

## What is in the repository

Only a **sample** is committed, to keep the repository small: `data/sample/*_player0_session0.csv.gz`
(player 0, session 0: 22,890 raw IMU rows, 23,845 label rows, 11,923 feature frames; about 6 MB), plus `players.csv`.
The sample files have exactly the same columns as the full files described above.

The full dataset (12 players × 2 sessions, about 140 MB) is deterministic (seed 7). Regenerate it with:

```
py -3.11 export_dataset.py
```

`notebooks/forehand_walkthrough.ipynb` needs the full dataset; its saved outputs show the full run.
